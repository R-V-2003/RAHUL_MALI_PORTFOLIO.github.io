Overview

What is DetNote?

DetNote is an online platform for booking Duolingo English Test (DET) exam slots. It helps students find available exam dates, compare pricing, and complete their booking — all in one streamlined experience.

Unlike PTENote where I redesigned an existing site, DetNote was a greenfield project — designed entirely from scratch. I owned the complete UI design process from initial concepts to dev-ready handoff.

Challenge

What needed to be solved?

🆕

Blank Canvas Design

No existing design system or brand guidelines. I needed to create the entire visual identity, component library, and page layouts from zero.

🧩

Complex Booking Flow

Exam booking involves multiple steps — selecting dates, locations, payment. The UX needed to feel simple despite the underlying complexity.

🌍

Global Student Audience

DET takers come from diverse countries with different devices and network speeds. The design needed to be universally accessible and fast-loading.

💳

Trust for Transactions

Users are paying for exam slots — the interface needed to convey professionalism and reliability to reduce drop-off during checkout.

Process

My design process

1. Competitive Research

Studied existing DET exam booking platforms and adjacent competitors (Pearson VUE, ETS) to understand industry UX patterns, trust signals, and common pain points in exam booking flows.

2. User Flow Mapping

Mapped the complete user journey: Landing → Explore Exams → Select Date/Slot → Review Details → Payment → Confirmation. Identified decision points and potential friction areas at each stage.

3. Wireframes & Layout Planning

Created low-fidelity wireframes focusing on information architecture — ensuring key elements (pricing, dates, CTAs) were prominently placed. Iterated on layouts for mobile and desktop breakpoints.

4. Visual Design System

Built a cohesive design system in Figma: color palette (warm coral tones + neutrals), typography scale (Inter), spacing tokens, button variants, card components, and form elements — all documented for developer handoff.

5. High-Fidelity Prototyping

Designed complete high-fidelity screens for all pages — hero, features, booking flow, pricing, and footer. Added interactive prototype flows in Figma to demonstrate the booking user journey for stakeholder review.

Solution

Key design decisions

🎨 Warm, Inviting Color Palette

Chose coral-to-orange gradients to feel approachable and energetic — differentiating from the cold, clinical UIs of traditional exam platforms.

📋 Clear Step-by-Step Booking

Broke the booking process into clear, numbered steps with progress indicators — reducing anxiety and drop-off during the multi-step flow.

🔒 Trust-First Layout

Placed security badges, student testimonials, and transparent pricing above the fold to build confidence before users enter the booking funnel.

📱 Responsive from Day One

Designed for mobile-first with component variants for tablet and desktop. Every form, button, and card adapts gracefully across screen sizes.

Reflection

What I learned

Designing 0→1 is fundamentally different from redesigning. Without an existing reference, every decision — from button radius to color temperature — requires intentional reasoning rather than incremental improvement.

Component systems save massive time. Building a proper design system early (even for a relatively small project) paid dividends when I needed to create new screens — consistency was automatic, not manual.

Booking flows need empathy. Users booking exam slots are often stressed — the design should reduce friction and anxiety, not just look good. Every micro-interaction matters in a transactional flow.
